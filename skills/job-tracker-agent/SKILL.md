# Job Tracker Agent

## Purpose and boundaries

Execute real research now, not a plan, fictional dataset, or demo-only handoff. This is an on-demand Perplexity Computer skill, not a running background agent or recurring schedule.

- **Private matching:** Use actual resumes from approved private files or this conversation. Never publish resumes, personal workflow, credentials, or personalized results to GitHub or the public jobs feed.
- **Any profession:** Derive roles, expertise, credentials, seniority, location, compensation, and sources from the supplied profile and actual resumes, not an accounting template.
- **Separate systems:** The public Vercel real-jobs feed is discovery infrastructure, not the user's authenticated private tracker. A public feed refresh does not update private matching or workflow.
- **Authorization:** Research and prepare the private result within the request. Apply it only to the authorized private workspace through its supported authenticated workflow. Do not contact employers, apply, impersonate a visitor, change repository code, push main, or deploy without separate approval.

## Execute

Read `references/execution.md` before starting a run. It defines required evidence, the scoring rubric, identity preservation, validation, and authenticated delivery.

1. Locate the approved tracker refresh request, current private snapshot/workflow, and actual resume files. Validate the request, profile, descriptor mappings, and fingerprints before scoring. Ask only for genuinely unavailable private inputs.
2. Load the research/search skill for real-source research. Search every configured source, keep a timestamped source ledger, fetch exact employer/ATS requisitions, and verify current availability. Record blocked/failed sources as failures, never zero results.
3. Deduplicate without losing stable `job_id` or user history. Apply profile hard filters and score each eligible lead against exactly one supported actual resume, with eight weighted, evidence-grounded components and any required-credential cap.
4. Assemble a complete private snapshot using current repository schemas, never bundled schema copies. Preserve current status, favorites, notes, actions, contacts, dates, and explicit blanks. Mark incomplete coverage `partial`; do not silently rescore historical records or archive jobs without direct recheck.
5. Run schema and semantic validation using the repository validator. If authorized authenticated write access exists, preview/apply through the same viewer's workspace/API/import path with revision conflict protection, then reread and verify. Otherwise deliver validated private JSON and the exact write blocker. Never claim import success without readback.

## Completion report

State real leads verified, exclusions, source failures, resume/input blockers, snapshot validation outcome, and whether the private workspace was actually updated or only a validated artifact was prepared. Use current timestamps and real evidence URLs. Keep unknown qualifications, pay, travel, availability, hiring probability, and process speed unknown unless supported.

## Input/output example

**Input:** “Refresh my real job tracker using the exported request and the actual resume documents attached here. Keep my application notes and favorites.”

**Expected output:** Execute source checks against that request and those documents. Produce a schema-validated private JSON snapshot with actual verified postings only, the assigned resume alias and evidence for each scored lead, source failures, stable IDs, and preserved workflow. If no postings qualify, return truthful empty new-lead results while retaining tracked history. If authenticated import is authorized and succeeds, report verified application; if access is unavailable, state that the JSON is ready but not imported and identify the exact blocker. This example intentionally contains no sample job records.
